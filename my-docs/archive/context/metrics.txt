METRICS REFERENCE -- every metric we care about, what it means, how it is computed
(logged 2026-09-14. dataset s28nsc, K=200. ct_key='celltypes', niche_key='niches_2D')
================================================================================

A "cell state" here = one (cell_type, niche) pair, e.g. "Tumor cells | Tumor surface".
s28nsc has 18 cell types x 9 niches = 146 pairs present in the ground truth.
How many have real single-cell signal (genes with pvals_adj < 0.05, of 960):
    >= 5 sig genes :  64   <- MIN_GENES=5 is the testability gate, so 64 IS THE CEILING
    >=10 sig genes :  47
    >=50 sig genes :  29
    >=100 sig genes:  13
SEACells reaches 19, scProto 14. BOTH are far from the ceiling of 64.


--------------------------------------------------------------------------------
GROUP 1 -- DGE: do metacells reproduce real single-cell biology?
code: interpretable_ssl/evaluation/niche_dge.py
--------------------------------------------------------------------------------

For one cell state, compare two gene-expression changes:
    truth[gene]    = logFC of that gene, this niche vs other niches, on REAL CELLS
    measured[gene] = the same comparison, but computed on METACELLS

pearson_r   PRIMARY. correlation between truth and measured. MetaQ's recipe.

            >>> NOT computed on all 960 genes. niche_dge.py:222 does:
                    gt_sig = gt_df[ gt_df['pvals_adj'] < 0.05 ].head(100)
                1. keep only genes SIGNIFICANTLY DE in the REAL SINGLE CELLS
                2. the GT table is pre-sorted by |logFC| descending, so .head(100)
                   takes the 100 LARGEST real effects
                3. a state needs >= 5 such genes to be testable at all (MIN_GENES)
                Actual counts used: SEACells median 96 genes, scProto median 100.
                The gene set is IDENTICAL for both methods on the same state
                (verified), so the comparison is fair.

            >>> WHAT THIS MEANS FOR THE CLAIM. Because the genes are pre-selected
                for being real and large, pearson_r answers:
                  "given the genes we ALREADY KNOW are changed, do metacells
                   reproduce their magnitudes?"    <- a REPRODUCTION test
                NOT:
                  "do metacells DISCOVER the signal?"   <- a DISCOVERY test
                That is why nearly every state scores 0.85+ and why the methods
                look tied. The 'we find more cell states' claim is carried by
                COVERAGE (n_pairs), not by pearson_r. Do not let pearson_r do
                work it cannot do.

kendall_tau rank version of the same thing. robust to a few outlier genes.

tpr         SECONDARY, different question. SuperCell's recipe. Same gene filter as
            above (niche_dge.py:259, pvals_adj < 0.05), so it is RECALL: of the genes
            known DE in single cells, what fraction do the metacells also call
            significant under a size-weighted t-test? High tpr = enough statistical
            power. NOTE tpr is near-saturated for everything (0.95-1.00) precisely
            because the genes were pre-selected for being real -- it does NOT
            discriminate between methods. Do not lead with it.

HOW THE MEAN IS TAKEN (two-step macro average, niche_dge.py:283):
    step 1: within each cell_type, average over that cell type's niches
    step 2: average those per-cell-type numbers across cell types
    -> reported std is the std ACROSS CELL TYPES of the step-1 values
Reason for two steps: a cell type present in many niches would otherwise dominate.
Consequence: every cell type counts equally regardless of how many cells it has.


--------------------------------------------------------------------------------
GROUP 2 -- COVERAGE: how many cell states can we even see?
--------------------------------------------------------------------------------

n_pairs        the headline coverage number. How many (cell_type, niche)
               pairs had enough metacells to run the DGE test at all. A state with
               no dedicated metacell is INVISIBLE, so this is "how granular are we".
               SEACells bk0.2 = 19. scProto best = 14.

state_coverage same thing as a fraction. NOTE: verify its denominator before
               quoting it -- it does not equal n_pairs/146.

Why it matters: a method can score high pearson_r by only resolving the easy,
abundant states. ALWAYS read pearson_r and n_pairs together.


--------------------------------------------------------------------------------
GROUP 3 -- PURITY: is each metacell one thing, or a mixture?
code: interpretable_ssl/evaluation/collapse_diagnostics.py
--------------------------------------------------------------------------------

For each metacell, take the fraction of its cells sharing the most common label:

    purity[m] = (count of most common label in metacell m) / (n cells in metacell m)

Three label choices:
    ct_purity     label = cell_type only
    niche_purity  label = niche only
    joint_purity  label = cell_type + "|" + niche   <- THE HEADLINE ONE
                  joint is the honest one because neither failure mode can game it:
                  collapsing into giants wrecks niche purity, and fragmenting into
                  singletons is exposed by the macro/micro gap below.

TWO WAYS TO AVERAGE -- WE CARE ABOUT BOTH (macro_micro_gap, collapse_diagnostics.py:67):

    micro = size-weighted      each CELL counts equally
            micro = sum over m of ( purity[m] * size[m] ) / sum over m of size[m]
            inflated by COLLAPSE: one giant metacell of the majority class scores
            well for free.

    macro = unweighted         each METACELL counts equally
            macro = mean over m of purity[m]
            inflated by FRAGMENTATION: a singleton metacell is trivially 100% pure.

    gap   = macro - micro
            ~0        = healthy, big and small metacells are equally clean
            much > 0  = the BIG metacells are the dirty ones -> collapse signature

>>> STATUS OF THE DATA WE HAVE: every purity number currently saved is MICRO ONLY. <<<
    `collapse_summary` already computes purity_gap, but build_report.py keeps only
    cs['purity_micro'] and drops cs['purity_gap'] before writing the CSV. ct_purity
    and niche_purity go through size_weighted_purity(), which has no macro version
    at all. So macro joint/ct/niche purity needs ONE cheap eval re-run -- it is a
    few-line change, not new training.


--------------------------------------------------------------------------------
GROUP 4 -- COLLAPSE DIAGNOSTICS: is the run degenerate?
--------------------------------------------------------------------------------

n_metacells    how many prototypes actually got cells. Should be 200. Was 15 under
               the old broken loss.
median_size    median cells per metacell. mean is pinned at N/K = 58423/200 = 292 by
               arithmetic, so the MEDIAN is what tells you about skew.
largest_share  fraction of ALL cells in the single biggest metacell. Rising = collapsing.
               Healthy ~0.006-0.03. Old broken loss hit 0.44.
dip_p          Hartigan dip test on log10(sizes). SMALL p = size distribution is not
               one hump = there is a cliff = collapse. Healthy runs are large p.
