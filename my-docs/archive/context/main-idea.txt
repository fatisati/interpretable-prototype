  *** WHAT I EXPECT FROM THE LOSS -- this is the requirement, not a nice-to-have ***

  If a cell state is really there in the gene expression, the loss must find it.

  Concretely: if a (cell_type, niche) state has genes that are differentially
  expressed in the REAL SINGLE CELLS, then that signal is present in the gene
  expression matrix. The encoder reads the gene expression matrix. So the
  information IS available to scProto. If scProto does not end up with metacells
  for that state, that is a failure OF THE LOSS (or of the model), not a
  missing-input problem. I should not need to hand the model spatial coordinates
  as an extra input to recover a state whose signal is already in the expression.

  This is the bar. Measured against it right now (s28nsc, bk02, K=200):
      SEACells resolves 19 states, scProto 14, and the 5 scProto misses are REAL
      (25-87 significantly DE genes each in single cells, pearson_r 0.85 when
      SEACells resolves them). scProto finds NO state SEACells misses.
      -> by my own criterion, the loss is not yet doing its job.

  [VERIFIED FROM CODE, 2026-09-14 -- your reading is CORRECT.]
  This is `lambda_proto_usage`. The best run uses proto_usage_mode='ema'
  (scproto.py:1516-1525). What it actually computes:

      strongest_cell[p] = max over cells of assign[cell, p]   # MAX, not a sum
      usage_loss        = -log( EMA(strongest_cell) ).mean() / (1 - alpha)

  So it asks exactly one question: "does every prototype have at LEAST ONE cell
  that strongly belongs to it?" -- which is what you guessed.

  Two consequences worth remembering:

  1. It SAYS NOTHING ABOUT SIZE. A prototype with 1 confident cell and a
     prototype with 5000 cells both satisfy it equally.
  2. It SATURATES. Once strongest_cell is near 1, -log(strongest_cell) is near 0
     and there is no gradient left. It stops one prototype from dying; it does
     not shape the size distribution at all.

  WHAT THIS DOES *NOT* SETTLE: which force actually equalizes metacell sizes.
  The code argument above only shows the usage loss has no DIRECT headcount term.
  It can still change sizes INDIRECTLY, and no run so far separates it from gamma,
  so nothing here is attributed. See context/EXPERIMENTS.md for the measurements and
  the one run that would settle it.
