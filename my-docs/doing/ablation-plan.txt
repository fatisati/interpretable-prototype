THE QUESTION
------------
4 loss terms. Does each earn its place, and at what weight?

  cohesion_gram  "same 2-hop neighbourhood"   }  swept SEPARATELY, so we can see
  cohesion_aff   "directly connected"         }  which kernel does the work
  community      "does it generalise"
  recon          "is z still about genes"

One dose point at 0 per term = that term's ablation arm. We do not run the
ablation as a separate experiment.


BASE LAMBDAS  (pbmc-immune, share vector B, measured 2026-10-06, run tag d57)
-----------------------------------------------------------------------------
Share vector B = equal share per SUBSYSTEM, not per term:

    cohesion_gram  1/6  }  cohesion  = 1/3
    cohesion_aff   1/6  }
    community      1/3
    recon          1/3

    lambda_i = share_i / median_gradnorm_i

               gradnorm (median)    lambda
    gram           0.043930         3.794
    aff            0.026046         6.399
    community      7.7399           0.04307
    recon          16.325           0.02042

Measured over ONE full pass, weights frozen and VERIFIED frozen, probed every
5th step. Mean and median agreed to <1%. Reproducibility verified: a duplicate
run matched on every printed digit.

Note the base is computed per SUBSYSTEM (so cohesion gets 1/3 total, split
evenly between its two kernels) but each of the four terms is then swept
INDIVIDUALLY.

WHY community gets the longest curve: on immune, the best arm we already have

known-good point, with 4x = 0.1723 above it. There is no equivalent evidence
for the other three terms, so they get shorter curves.

RUN ORDER: arms 1-3 FIRST. Without the noise floor a 2% gap between dose
points cannot be told from run-to-run variance.

If budget allows 2 more arms (~$1.3): add gram 2x (7.588) and aff 2x (12.80)
to turn the two kernel curves into real curves instead of on/off.


WHAT WE EXPECT  (written BEFORE running -- do not edit afterwards)
------------------------------------------------------------------
  drop gram      -> test cohesion drops; rare metrics drop. gram is the 2-hop
                    kernel, so losing it should hurt cells that share a
                    neighbourhood without touching directly.

  drop aff       -> test cohesion drops; rare metrics drop. aff is 1-hop, so
                    losing it should hurt locally-tight groups.
                    (D39 on s28nsc: gram+aff beat either alone, and gram-only
                     left 5/200 dead prototypes while aff-only left 0. So if one
                     kernel matters more, expect aff.)

  drop cohesion  -> both of the above, larger. Rare metrics worst hit, because
                    cohesion is scale-free: a 20-cell metacell scores like a
                    2000-cell one, which is what protects rare types.

  drop recon     -> batch entropy and cross-batch homogeneity drop; purity and
                    rare metrics drop.
                    (with recon off NOTHING pushes batch info out of z: the
                     batch embedding has no other consumer, and the affinity
                     graph is built from PCA of X, which is batch-confounded)

  drop community -> held-out rare metrics and purity drop, and the HELD-OUT
                    penalty is larger than the FULL-dataset penalty.
                    (the discriminating test. Cohesion can lower itself by
                     MOVING PROTOTYPES, which does nothing for an unseen cell.
                     Community has prototypes detached, so the only thing it can
                     change is the encoder's input->z map, which a new cell
                     inherits. If dropping community costs nothing on held-out
                     cells, it is not earning its place and we drop it. Clean
                     result either way.)


METRICS  (frozen before launch, nothing added later)
----------------------------------------------------
MAIN:
  rare homogeneity         per rare cell, pooled across batches
  rare F1                  per batch, then across batches
  rare coverage            per batch, then across batches
  cross-batch homogeneity  rare cell's mates from a DIFFERENT batch
                           -- the most direct test of the recon prediction
  batch entropy            per metacell, size-weighted
  cell-type purity         per metacell, size-weighted -- report FULL and TEST
  test cohesion            per cell, held-out only, full graph

SECONDARY (reported, not a main metric):
  test modularity          per-batch, edges touching a held-out cell
                           -- demoted on purpose: not a headline claim. But it
                           is still the most DIRECT probe of community's
                           mechanism, so report it for the community arms.
  n_unused_protos          health, not quality

All from rare_metrics_paper() + score_nodeheldout(), same code for every arm.

CAVEAT for the caption: cohesion is BOTH a training term and a reported metric,
so "cohesion improves cohesion" is circular. The non-circular claims are (a) it
is measured on HELD-OUT cells, so generalisation not fit, and (b) removing it
hurts rare metrics and purity, which it does not optimise.


HOW WE PICK THE WINNER  (declared before seeing any result)
-----------------------------------------------------------
  GATE       n_unused_protos == 0  -- an arm with dead prototypes is INVALID,
                                      not "worse"
  PRIMARY    rare homogeneity, held-out
  GUARD      held-out purity must not fall more than 1 noise-floor std below
             base -- so we cannot "win" on rare cells by wrecking everything
  SECONDARY  rare F1, rare coverage, cross-batch homogeneity, batch entropy,
             test cohesion, test modularity -- reported, NOT selected on
  TIE-BREAK  within 1 noise-floor std on primary -> prefer higher batch entropy

WHY rare homogeneity is primary and NOT rare F1 / coverage, despite all three
being rare metrics. It is a precision argument, measured on immune:

    metric                  std     across            SE of the mean
    rare homogeneity        0.272    4,386 cells         0.0041   <- most precise
    cell-type purity        0.180      300 metacells     0.0104
    rare coverage           0.267        5 batches       0.1194   <- 29x noisier
    rare F1                 0.267        5 batches       0.1194

The +/-0.25-0.40 figures quoted in RESULTS.md are the SPREAD of the
distribution, not the error on the mean. Divided by sqrt(n), rare homogeneity
is the MOST precisely estimated metric in the whole set -- 2.5x better than
purity. Coverage and F1 average over only 5 batches, so they cannot carry a
selection decision; they are reported as the payoff.
(The rare-cell count above used a <5% per-batch frequency proxy; the code's
actual definition is rare_quantile=0.25, which selects MORE cells, so the SE is
at most this and the conclusion only strengthens.)

These are WITHIN-run standard errors. The real uncertainty is run-to-run, which
arms 1-3 measure. If the 3-seed spread on rare homogeneity turns out larger than
the base-vs-arm differences, we fall back to purity as primary -- declared NOW,
not after seeing results.

Every arm gets a verdict: works / fails / abandoned. No arm left inconclusive.

KNOWN LIMITATIONS  (same in every arm, so they cannot confound the sweep)
-------------------------------------------------------------------------
  - one term at a time, so INTERACTIONS are unexplored. Say it in the caption.
  - gram and aff get on/off only, not full dose curves, unless the 2 extra arms
    are added. So stage 1 says WHETHER each kernel matters, not at what weight.
  - coh_mem_hlife = 0.0 (no age decay). CLAUDE.md 9d says derive it as
    c*N/uniq; no coh_mem_drift measurement exists yet, so d59 used 0 and we
    match it.
  - epsilon calibration FAILS on all 5 datasets and falls back to effk=5.0, a
    constant nobody chose. Confirmed in the d57 log. Identical in every arm.
  - in the "recon 0" arm, freeze_batch_embedding=True becomes a no-op, since
    nothing else uses the batch embedding. So that arm is "no recon AND
    effectively no batch mechanism".
  - the three existing immune arms (d59 / d59_v2 / d59_v3) were run BEFORE the
    D57 prototype-init fix, so they differ in prototype init as well as in
    lambda. Use them to orient the grid, not as arms of this experiment.
