# The headline metric is under-specified. Modularity lacks a formula, resolution, or null model (App F l.486-488), so the numbers are neither reproducible nor comparable across the different-sized batches Table 1 averages.

Thank you — we will add this specification to Appendix F for the camera-ready version. To state it precisely here: modularity is computed as the standard weighted Newman modularity,
Q = (1/2m) · sum over clusters k of [ e_k − d_k^2/(2m) ]
where e_k is the total edge weight inside cluster k, d_k is the sum of degrees of cells in cluster k, and 2m is the total edge weight in the graph. This is computed directly on the continuous RBF-kernel affinity weights, with no thresholding or binarization, using the standard configuration-model null (d_k^2/(2m)) and a fixed resolution parameter of gamma = 1 (not swept or tuned). We will state the formula, the resolution parameter, and the null model explicitly in the revised appendix.

On the circularity concern (modularity as training loss, early-stopping criterion, and headline metric all at once):

We agree modularity as reported is defined relative to the same affinity graph used in training, and we address this directly with the held-out-edge experiment below rather than
 arguing the original comparison was already independent. 
 In that experiment, scProto is trained and early-stopped using only the visible 80% of the affinity graph's edges; 
 the reported held-out modularity score comes from a separate scoring pass against the hidden 20% of edges, 
 which never enter the loss or the early-stopping signal at any point during training. 
 This gives an evaluation that is structurally independent of what the model was trained and selected on. 
[Held-out modularity results reported above / cross-reference to that section.]

On comparability across differently-sized batches (Table 1's mean ± std averages):
We report modularity per batch, rather than a single pooled number, specifically to show that scProto preserves 
the affinity graph's structure consistently across every biological batch in a dataset — not just on average, 
or on whichever batch happens to dominate a pooled score. 
Every method reported in Table 1 (scProto, SEACells, MetaQ, scPoli (cVAE), Parametric UMAP) is scored against the identical set of per-batch subgraphs within a given dataset, 
so any batch-to-batch variation is a shared covariate across every row of that column — 
it affects all methods equally and does not bias the cross-method comparisons the table is used to support. 
All claims we draw from these numbers are within-dataset, cross-method comparisons (e.g., scProto vs. SEACells on Pancreas); we do not compare raw modularity magnitudes across 
datasets. We will state this explicitly in the text.
