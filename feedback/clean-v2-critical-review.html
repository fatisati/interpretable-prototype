Executive summary

clean-v2 is a well-built benchmark attached to a claim that its own first results and the published literature do not support. The pipeline is worth keeping. The claim, the scoreboard and the dataset strategy need to change before more datasets are run.

What it is. A restart of scProto as an evidence-first project: show that batch correction plus clustering, and SEACells, lose rare cell types, then show scProto fixes it. Three baselines exist (scVI, PCA control, SEACells), one dataset has committed results (heart), and scProto itself is not in the branch.

Main strengths. Claim and metrics written before running; a null result reported openly; one shared split, graph and cluster count for all methods; an uncorrected control; full run records; a real finding that the scIB trio's counts are not raw.

Main red flags.

  1. The premise is contradicted. scVI matched or beat the uncorrected control on rare cells on heart. Published benchmarks mostly list scVI and scANVI among the methods that keep rare types; they blame Harmony and Seurat.
  2. The dataset search has turned into looking for a dataset where the baselines fail. The seven selection criteria were written after the null result.
  3. The ground-truth graph is batch-confounded and the planned comparison is circular. 56% of its edges join cells of the same donor, against 8.4% expected. scProto would be trained on this graph and scored on it.
  4. No statistical power. 44 rare test cells, one run per method, and a rerun moves rare F1 by 0.08 to 0.15.
  5. Metric and baseline gaps. About 248 clusters for 11 cell types; home-made metrics instead of the field's; SEACells run in a way its authors do not recommend; Harmony, BBKNN and ComBat not written.

Datasets. The best-supported target is one disease-relevant rare state followed across modalities: aberrant basaloid cells in pulmonary fibrosis (Adams 2020 and Habermann 2020 dissociated, Vannan 2025 Xenium). HLCA core is the reviewer-expected benchmark, and SEA-AD MERFISH the second spatial case. Heart fine labels, Haber, Moffitt and the single-animal Allen brain atlas should be dropped. None of the new candidates has been downloaded or audited yet.

Plan. Freeze the claim and scoreboard, measure the seed noise, add the three missing baselines, then run a planted rare-state test with a known answer. That test decides in days whether any baseline loses a state the uncorrected data can still see. Only datasets passing cheap checks get full baselines, and scProto runs only where a gap was shown, compared against its own backbone.

Recommended reframing. Lead with batch-aware metacells and niche-defined rare states, where no direct competitor was found, and stop leading with "scVI loses rare cells". If the planted-state test and two real datasets show no gap, withdraw the rare-cell motivation.

What clean-v2 is

clean-v2 is a restart of the scProto project as an evidence-first benchmark: prove that existing methods lose rare cell types, then show scProto fixes it. It is a new history of 24 commits (15 to 22 November 2026, one author) and contains no scProto code yet; scproto/ is empty.

The claim under test (Task 1, tasks/rare_cell_preservation.md). Batch correction followed by Leiden clustering absorbs a rare sub-state into an abundant type. A second claim says SEACells cannot form a metacell for a type that is rare in every batch. scProto is meant to fix both by following a cell-cell affinity graph.

The pipeline (docs/architecture.md). Five stages, each writing files that later stages only read:

  1. Dataset prep: raw file to an HVG-selected .h5ad.
  2. Evaluation setup: one train/test split (80/20, stratified on cell type and batch), an affinity graph, and a shared cluster count K = cells / 75.
  3. Baselines: each writes an embedding or assignments, clustered to the shared K.
  4. Metrics: purity, agreement (global, within-batch, cross-batch), rare coverage, rare F1, cohesion, neighbor metrics, and a frequency-dependence check.
  5. Results: generated tables and figures; the verdict is written by hand.

Strengths

The engineering and the honesty of clean-v2 are well above the previous branch; the weaknesses below are about the science, not the code.

  • Evidence before method. The task file states the claim, per-baseline mechanisms, metrics and expectations before any run. This answers the reviewer question "is the problem real?" before the method is shown.
  • A null result was reported, not buried. The first heart run contradicted the expectation. The task file records it under Revisions with the cause the authors believe, and the results script was changed so it no longer prints a verdict.
  • Shared inputs by construction. Split, affinity graph and cluster count are created once and only read afterwards. Baselines fail loudly if those files are missing or built with other parameters.
  • An uncorrected control. PCA + Leiden separates "integration lost the type" from "clustering lost it". Most integration papers omit this.
  • Neighbor metrics next to cluster metrics. Embedding-level loss can be told apart from clustering-level loss.
  • Raw-count audit. The scIB trio was checked directly and found to have non-integer counts (pancreas 42.8%, lung 91.6%, pbmc_immune 7.9%), so they were removed from negative-binomial use. This was a real, previously unnoticed problem.
  • Provenance. Every output has a config sidecar with the command, git commit, dirty flag and package versions. Decision records exist for dataset choice and the rare-cell rule.
  • Cheap pre-checks and a planted-state test are already proposed (task file, "Cheap checks before running baselines"). Check 7, a planted rare state with a dial, is the strongest idea in the repo.
  • It runs elsewhere. All five stages ran unchanged on a second machine (Mac, 2026-11-22), and a self-contained sanity test exists.

Weaknesses and red flags

The four most serious problems are about what is being claimed and how it is scored; the rest are fixable gaps. Ordered by severity.

01The premise about scVI is contradicted by the project's own data and by published benchmarks

The task file names scVI's weakness as "the specific weakness scProto's affinity guidance is meant to fix". The evidence points the other way.

  • Own data: scVI beat the uncorrected control on rare cells on heart, with both label sets.
  • scIB describes scVI, scANVI, Scanorama and Harmony as retaining rare cell types, and singles out Harmony for the lowest isolated-label F1 among top methods on the immune task.
  • HLCA: the three rare airway types formed separate clusters after scANVI; Harmony and Seurat RPCA failed.
  • scDREAMER lists scVI among the three methods that kept lung ionocytes separate. scIB-E reports scVI with the highest within-cell-type conservation score.
  • Against scVI: scDML (missed B-cell subtypes on lung) and scCRAFT (32.2% of rare islet cells had a wrong-type neighbour, against 3.5% for scCRAFT).

The literature blames Harmony and Seurat far more than scVI. scProto is itself built on a conditional VAE, the same model family, so "VAEs lose rare cells" is also an awkward message.

02The dataset search now looks like searching for a dataset where the baselines fail

The expectation was written, the first run contradicted it, and the response was a seven-point list of dataset properties under which the baselines should fail. Each item is defensible alone. Together, and written after the result, a reviewer will read them as tuning the benchmark to the conclusion. The README says a task file is "never edited after results exist"; it was revised twice on 22 November. The edits are logged honestly, which helps, but the list needs to be frozen before the next run and every dataset tried must be reported, including heart.

03The "ground-truth" affinity graph is batch-confounded, and the planned comparison is circular

The graph is a k = 15 kernel on uncorrected PCA of all batches. Measured on heart: 56% of its edges join two cells of the same donor, against 8.4% expected if the graph ignored donor. Part of that is real biology, because donors differ in cell source (nuclei, whole cells, CD45-sorted) and composition. Consequences:

  • Cohesion rewards keeping batches apart. The uncorrected control sits near the ceiling by construction (the task file admits this), and good integration is penalised.
  • SEACells is given this graph as its kernel and is then scored on cohesion against it.
  • scProto will be trained to follow this graph and scored on the same graph. A win on cohesion would prove only that the loss was optimised.

Cohesion can stay as a diagnostic. It cannot be evidence for the method.

04The rare-cell numbers have almost no statistical power

The test half has 44 rare cells; most rare groups hold one to three cells; every method was run once. Rerunning moved rare F1 by 0.08 to 0.15, as large as the differences being interpreted. Nothing has a confidence interval across seeds. Subsampling makes this worse: the heart file is 18,641 of 486,134 cells, and the HLCA cap changes how rare the target types are by about tenfold (the repo's own note).

05Several metrics measure something other than what they are named for

  • K = cells / 75 gives about 248 clusters for 11 cell types. Purity is 0.97 for every method, so it cannot discriminate. A 30-cell state can never be the majority of a typical 71-cell cluster unless the method isolates it into a much smaller one.
  • Cohesion averages a sparse 15-neighbor graph over about 71 cluster members, so it mostly tracks cluster size; small clusters score high. This is why rare groups score higher than common ones.
  • Within-batch neighbor same-type share is capped at (n − 1) / 15 for a type with n cells in the batch, so it falls with rarity for every method.
  • The rare rule depends on label granularity. With 65 fine labels, vCM5 at 0.3 to 0.5% of a batch is not flagged rare in most batches.
  • Rare F1 averages over (type, batch) pairs, many with one cell, so single cells decide the mean.
  • None of these are the field's metrics. Reviewers will ask for isolated-label F1 and silhouette (scIB, Open Problems) and the HLCA rare-cell recall and precision.

06The SEACells comparison is open to a strawman objection

The SEACells paper says metacells can be computed per sample and integrated afterwards. The metacell review gives two routes: per sample then integrate, or correct batch first then build metacells. Running SEACells on pooled, uncorrected cells is neither. The task file also describes SEACells as building metacells within a single batch, which is not how the baseline script runs it. Fair baselines are per-sample SEACells and SEACells on a corrected embedding, plus MetaQ, which already claims rare types down to 0.01%.

07The baselines most likely to show the gap are not written

Harmony, BBKNN and ComBat are named in the task but absent. They are the cheapest to run and the ones the literature reports failing. Also missing: scANVI, scPoli (scProto's own backbone, the fairest ablation), Scanorama, and the direct competitors scDML and scCRAFT.

08Mechanisms are asserted, not cited or tested

The per-baseline explanations (ComBat's shared factor, Harmony's diversity term, scVI's KL pull) read as established fact. None has a reference or a test. The literature search found no paper showing ComBat or BBKNN losing a rare type, and no published statement that SEACells fails on rare types across batches.

09The method is absent, and the older branch's negative findings were not carried over

clean-v2 has no scProto code. The older branch's commit log records that stage-2 training was "net harmful as configured" (D59), that a rare-purity gain was retracted as noise (D60), and that the negative-binomial variant was worse than MSE on held-out metrics (D64, one seed). clean-v2 documents none of this, so the benchmark is being built for a method whose rare-cell advantage has not yet been observed.

10Smaller gaps

  • Marker survival after gene filtering (the task's own item 3) is "?" for almost every dataset.
  • The processed heart file has a different checksum on a second machine with the same raw file; the cause is unknown.
  • HLCA fine labels were built with scANVI (the repo's note), which favours scVI-family methods.
  • Modal runs get no run record.
  • The verdict file the README requires does not exist.

What the current results show

The results so far do not support the claim, and they are too small to refute it either. Three sets of numbers matter.

1. Heart, broad labels (committed, official)

scVI is at or above the uncorrected PCA control on every rare-cell metric.

2. Heart, fine labels (committed what-if, 65 cell_states)

Nothing recovers the rare states, including the control. Test rare F1 is 0.103 for PCA and 0.247 for scVI; train is 0.076 and 0.086. vCM5 cells share a cluster with other vCM5 cells about 1 to 4% of the time under plain PCA. A state the uncorrected data cannot separate cannot be "lost by correction", so this label set cannot show the gap. This contradicts the reading in docs/dataset-options.md that heart fine labels "fit the claim best".

Frequency dependence

The task expected every metric to fall as a type gets rarer. scVI's cohesion rises instead (Spearman −0.55 on test). The strongest positive trend, within-batch neighbor same-type share (Spearman 0.81), is partly mechanical: a type with n cells in a batch can have at most n − 1 same-type neighbors out of 15.

The best-supported target is one rare, disease-relevant state followed across modalities: aberrant basaloid cells in pulmonary fibrosis, in two dissociated atlases and one Xenium atlas, with HLCA as the published-failure benchmark and SEA-AD MERFISH as the second spatial case. No candidate found meets all seven of the task's criteria; label provenance is the usual failure.

Ranking

  1. Pulmonary fibrosis trio: Adams + Habermann + Vannan. One validated, clinically important rare state; labels independent of integration in the dissociated data; about 14 cells per diseased lung; two labs for a real batch effect; and a spatial atlas where the state is niche-bound. It tests the transcriptomic and the spatial graph on the same biology.
  2. HLCA core, resampled without the cap. The reviewer-expected benchmark with a published failure of Harmony and Seurat RPCA. Score against original per-study labels and marker genes to answer the scANVI-label objection.
  3. SEA-AD MERFISH. The only spatial candidate with many donors and independently derived labels.
  4. Bone marrow with protein-backed labels (Zhang 2024, or NeurIPS 2021 as the practical fallback).

Two cautions on the top pick: a state that exists only in diseased lungs is confounded with condition, so the test must be run among diseased donors; and the 483-cell total across 50 lungs is workable only if scored with seeds and per-donor intervals.

Recommended plan

Freeze the claim and the scoreboard first, find out cheaply whether any baseline loses a rare state at all, and only then spend time on new datasets and on scProto. Each step names what would stop or redirect the work.

Step 0. Decide the claim a decision for the authors, before any run

The recommendation is to stop presenting "scVI loses rare cells" as the motivation and choose between two framings the evidence can support:

  • A. Batch-aware metacells that keep rare states. Baselines: per-sample SEACells then integration, SEACells on a corrected embedding, MetaQ, Harmony or scVI followed by clustering.
  • B. Rare states defined by niche. A spatial affinity graph recovers states that expression-only integration merges into the parent type.

Both can be in one paper. A is the safer core; B is the more distinctive result if it works.

Step 1. Freeze the scoreboard about 2 days, no new data

  1. Add the field's metrics: isolated-label F1 and silhouette, and HLCA-style rare-cell recall and precision. Keep the home-made metrics as secondary.
  2. Demote cohesion to a diagnostic, or rebuild the graph within each batch so it no longer rewards batch separation. Never report it as evidence for a method trained on that graph.
  3. Report rare metrics per rare state with its cell count, pooled over batches, with a minimum of about 30 cells in total. Drop the mean over one-cell groups.
  4. Report at two cluster counts: the metacell scale (cells / 75) and a cell-type scale. A result that holds at one only is a clustering effect.
  5. Run every method with at least 5 seeds and report mean ± std and the interval. Write the pass rule now, for example: "a gap exists if the baseline's rare recall is below the uncorrected control's by more than twice the seed std".
  6. Commit split.csv and cluster_config.json per dataset so every machine uses the same ones.
  7. Write the missing results/rare_cell_preservation.md verdict for heart: no gap, with the reason.

Step 2. Measure the noise floor half a day

Run PCA and scVI with 5 seeds each on heart. Expected: rare F1 std near 0.05 to 0.10, which would confirm that no single-run rare comparison so far means anything. If the std is below 0.02, the cross-machine difference is an input problem and must be traced first.

Step 3. Write the three missing baselines 1 to 2 days

Harmony, BBKNN and ComBat adapters, plus per-sample SEACells. They are fast, and they are where the literature reports the failure.

Step 4. Planted rare state, the decisive cheap test 2 to 3 days

Take a common type in a dataset with raw counts (NeurIPS bone marrow, 12 batches). Pick about 5 cells per batch and raise a small gene set by a controlled factor. Sweep the factor and the number of genes. For each setting, score whether each method isolates the planted cells, against the uncorrected control.

  • Expected if the claim holds: some baseline loses the state at an effect size the uncorrected control still detects.
  • If every baseline tracks the control at every setting: claim 1 is false for these methods. Do not look for another dataset. Move to framing A or B only.
  • This test needs no one's labels, so it also answers the circular-label objection.

Step 5. Cheap checks on real data, then go or no-go per dataset 2 to 3 days

Download Adams and Habermann, and resample HLCA core without the per-type cap. For each rare state run the task file's checks 1 to 4: cells per batch, marker genes kept after gene filtering, visibility within one batch in plain PCA, batch-effect strength. A dataset where the uncorrected control cannot see the state is dropped before any training, as heart fine labels should have been.

Step 6. Full baselines on datasets that passed, and a written verdict

All baselines, 5 seeds, the frozen scoreboard. The verdict for each dataset is one of: gap exists, no gap, inconclusive because of a named reason. Report every dataset tried.

Step 7. scProto, only where a gap was shown

  1. Port the trainer into scproto/ with the lessons of the older branch written down (D59 to D64).
  2. The key comparison is scProto against its own backbone (scPoli) with the same clustering, so the gain is attributable to the affinity term.
  3. Judge it on label-based metrics. A cohesion gain on its own training graph does not count.

Step 8. Spatial extension after step 7 works on dissociated data

Transfer the basaloid labels from Adams and Habermann to the Vannan Xenium data, so labels do not come from clustering the spatial data. On SEA-AD, first check whether 140 genes separate the Sst supertypes in one donor. Compare a transcriptomic graph against a spatial graph in scProto, with the same baselines.

What to drop

  • Heart fine labels, Haber, Moffitt, Allen whole-brain (Yao) as evidence datasets.
  • Cohesion and purity as headline metrics.
  • Pooled, uncorrected SEACells as the only metacell baseline.
  • Any further edit of the dataset criteria after step 1.

Stop rule

If steps 4 and 5 show no baseline losing a state that the uncorrected control can see, on two datasets, the rare-cell claim should be withdrawn as the paper's motivation. The remaining contribution to test is batch-aware metacells with held-out cell placement and niche-aware prototypes, judged on their own merits.

What was not verified, and open questions

This review rests on the clean-v2 files, one local rerun on heart, and a web literature search; the limits below apply.

Not verified

  • No new dataset in the candidates section was downloaded or audited. Raw-count status, label columns and per-donor counts of the rare states must be checked directly before any is adopted.
  • Literature statements come from the linked pages, mostly PubMed Central full text read through a summarising tool. Numbers that appear only in figures or supplements could not be read, including per-method isolated-label scores in scIB and HLCA.
  • Cadinu 2024's venue and the Zhuang atlas details came from search snippets only.
  • "No published batch-aware metacell method" and "no paper shows ComBat or BBKNN losing a rare type" mean no search hit was found, not that none exists.
  • The cross-machine difference in PCA rare F1 (0.696 against 0.846) has an unknown cause. The processed file's checksum differs; whether the gene set, the split or only the file encoding differs was not checked.
  • The affinity graph's same-donor share (56%) was measured on the locally rebuilt graph, and donor is mixed with cell source and composition in heart, so the technical share of that number is unknown.
  • The local SEACells and scVI numbers are one seed each.
  • The older branch's findings (D59 to D64) were read from commit titles and its instruction file, not from the full decision records.

Questions for the authors

  1. Which venue and date is clean-v2 aimed at? The plan above is about three weeks before scProto is run.
  2. Is the paper's core claim rare-cell preservation, or batch-aware metacells with rare cells as one benefit?
  3. Was the dataset criteria list meant to be frozen as of 22 November?
  4. Will scProto in clean-v2 be the D63 recipe from the older branch, or a new design?
  5. Is a spatial result required for the paper, or a bonus?
  6. Is there compute for 5 seeds per method on a 500,000-cell atlas, or should atlases be subsampled in a way that keeps true rarity?
